# Onboarding 问卷流程契约（ticket 07）

起步流程第 1 步的对话式 onboarding 问卷：**8 题、一问一答、答案确认后写入 `profile.md` 画像初值**。本契约是技能内接口——agent 按本文档执行对话收集答案，确认后交给 `scripts/profile.py`（`op=onboarding`）写画像。

按 spec「测试 seam」：对话式流程（计划生成、验收对话等）**不设自动化 seam**，构建后通过实际演练验证；本文档定义对话协议本身。写入路径由 `scripts/profile.py` 提供并有自动化测试（ticket 05，见 `resources/profile-contract.md` §7），本文档不再重复其输入输出格式，只规定对话层如何收集、校验、确认答案并调用它。

---

## 1. 目标与范围

- **目的**：建立用户画像初值（学习目标、水平自评、时间预算、风格偏好、压力自评、期望节奏、过往经历、复习意愿），作为后续计划适配性输入（spec「用户画像」）。
- **范围**：只做 onboarding 问卷本身（对话 + 写画像初值）。目标澄清与范围声明是 ticket 08、摸底测试是 ticket 09、计划生成是 ticket 10，**本流程不越界**。
- **硬约束**：一次只问一题，答完立即进入下一题；任何题目不得跳过、合并，也不得由 agent 代为作答或猜测默认值。

## 2. 8 题清单（固定顺序）

字段名（answers 键）与 `scripts/profile.py` 的 `ONBOARDING_FIELDS` **完全一致**，不得改名（`resources/data-formats.md` §3 字段稳定约定）；新增字段需同步改脚本与测试。

| # | 字段名 | 类型 | 对话问法 | 引导示例 | 校验规则 |
| --- | --- | --- | --- | --- | --- |
| 1 | `学习目标` | 文本 | "你想用 Python 做什么？请用一句话说清楚。" | "用 Python 处理 Excel 报表并做数据分析" | 非空。若回答过于模糊（如"学 Python"），追问澄清具体场景，直到能圈定子领域 |
| 2 | `Python 水平自评（1–5）` | 数字 | "你的 Python 基础打几分？1 到 5，1 = 完全没写过代码，3 = 能看懂简单脚本，5 = 能独立完成项目。" | "2" | 必须是数字；对话中先提示 1–5 范围，超出时请学习者重答（截断是 `profile.py` 的兜底，对话层应避免） |
| 3 | `每日时间预算` | 文本 | "每天能投入多少时间学习？" | "工作日 1 小时，周末 2 小时" | 非空，应含时间量；过于含糊（如"有空就学"）时追问具体时长 |
| 4 | `学习风格偏好` | 文本 | "你喜欢怎么学？视频、看书、动手敲代码，还是结合？" | "视频 + 动手练习" | 非空 |
| 5 | `压力承受自评（1–5）` | 数字 | "最近整体压力怎么样？1 到 5，1 = 很轻松，3 = 一般，5 = 压力很大。" | "3" | 必须是数字；同第 2 题，对话中先提示 1–5 范围 |
| 6 | `期望节奏` | 文本 | "希望学习节奏快还是慢？" | "平缓，每天学一点" | 非空；若只说"快/慢"，可追问"每天大概几个知识点"让答案具体 |
| 7 | `过往经历` | 文本 | "之前有过编程或 Python 经历吗？" | "无编程经验" | 非空；完全没有经历也明确回答"无"，不替学习者补默认值 |
| 8 | `复习意愿` | 文本 | "愿意为复习投入多少？" | "愿意每天 10 分钟" | 非空 |

1–5 自评题的锚点（对话中展示）：

- **Python 水平自评**：1 = 完全没写过代码；2 = 写过几行 / 只看过教程；3 = 能看懂简单脚本；4 = 能独立写小程序；5 = 熟练，能独立完成项目。
- **压力承受自评**：1 = 很轻松；2 = 比较轻松；3 = 一般；4 = 有点压力；5 = 压力很大。

## 3. 对话协议

1. **开场**：说明问卷目的与题数——"先花几分钟了解你，共 8 个问题，随时可以改答案。"
2. **一问一答**：按 §2 顺序逐题提问。数值题在问句中带上 1–5 锚点；每题收到答案后先校验（§2 校验规则），通过再问下一题。
3. **校验不通过**：提示原因并请学习者重答（"需要 1 到 5 之间的数字"），**不自动截断、不猜默认值**。
4. **答案模糊**：仅追问澄清，不替学习者作答、不推测补全。鼓励具体："具体一点，比如……"（用 §2 引导示例提示）。
5. **记录**：每题只记学习者明确给出的答案；对话中的解释、寒暄不写入答案。

## 4. 中途修改

- 任何时刻，学习者说"改第 N 题" / "重新答第 X 题" / "第 X 题我说错了"（N 为 1–8）→ **只重问该题**，收到新答案后覆盖；其余题不动。
- 已答题目在汇总确认时同样可改：学习者指哪题改哪题，改完重新汇总，直到学习者确认。
- 修改不改变题序：汇总与写入仍按 §2 固定 8 题顺序。

## 5. 结束确认与写入

1. **汇总**：逐条列出 8 题（`题目：答案`），请学习者确认或指出要改的题。
2. **确认后写入**：调用 `scripts/profile.py`，`op=onboarding`，`answers` 为 8 题答案对象（键与 §2 字段名一致）：

```bash
python scripts/profile.py <input.json> <output.json>
```

```json
{
  "op": "onboarding",
  "answers": {
    "学习目标": "用 Python 处理 Excel 报表并做数据分析",
    "Python 水平自评（1–5）": 2,
    "每日时间预算": "工作日 1 小时，周末 2 小时",
    "学习风格偏好": "视频 + 动手练习",
    "压力承受自评（1–5）": 3,
    "期望节奏": "平缓，每天学一点",
    "过往经历": "无编程经验",
    "复习意愿": "愿意每天 10 分钟"
  }
}
```

   输入输出格式、错误处理与退出码见 `resources/profile-contract.md` §2–§3；`date`/`profile_path` 缺省即可（默认系统日期、`profile.md`）。
3. **approval 护栏**：`profile.py` 会**原地改写** `profile.md`（`templates/profile.md` 模板生成或覆盖问卷初值），属持久层修改，执行前先经学习者确认（SKILL.md 护栏 approval）。
4. **写入后**：确认画像已建立（可简述"已记录你的画像"），进入起步流程下一步（ticket 08 目标澄清与范围声明）。

## 6. 边界与护栏

- 不越过问卷：此阶段不生成计划、不做摸底、不写范围声明（分别属 ticket 08/09/10）。
- 不替学习者作答、不推测默认值；**8 题必须全部由学习者给出答案**。
- 中途退出：学习者想退出时说明画像未建立、下次可重新开始；**不写半成品**——`profile.py` 要求 8 题齐全，缺字段会报错（profile-contract.md §2），对话层也不得用占位答案凑数。
- 已有画像重跑（学习者想重做问卷）：走同一流程，覆盖问卷初值；能力矩阵与增量记录保留（`profile.py` `onboarding` 行为，见 profile-contract.md §5）。
- 数值自评超范围：对话层先请学习者重答；`profile.py` 的 [1, 5] 截断仅作兜底，不依赖它。

## 7. 验证方式

- 本流程为对话式流程，按 spec「测试 seam」**不设自动化 seam**，构建后通过**实际演练验证**：模拟学习者一问一答（含一次中途修改）→ 汇总确认 → `profile.py op=onboarding` 写画像 → 检查 `profile.md` 原文（8 题初值、空矩阵、onboarding 日志）。
- 写入路径的自动化测试见 `scripts/test_profile.py` 的 `OnboardingTest`（ticket 05）：创建文件 / 覆盖保留矩阵 / 8 题校验 / 数值截断 / 缺字段报错等。
