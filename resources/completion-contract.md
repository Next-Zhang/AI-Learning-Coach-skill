# 完成度合成契约（ticket 04）

v0 混合式验收的量化逻辑 `scripts/completion.py`——统一契约：**agent 评分 + 学习者自评 → 完成度分**，按 7:3 合成、四舍五入到 0.5 档；难度反馈独立记录、不参与完成度分。脚本以「读输入文件 → 写输出文件」形式提供，纯 Python 标准库、无外部依赖，可在任意工作目录运行；只读计算，不改写任何持久层文件。

本契约是技能内接口：每日验收时 agent 与学习者各自给出 1–5 评分，脚本合成完成度分；难度反馈单独采集、单独记录（只影响后续计划难度档位，见 spec「混合式验收与完成度」）。合成规则与数据格式约定见 `resources/data-formats.md` §2。

---

## 1. 用法

```bash
python scripts/completion.py <input.json> <output.json>
```

- 退出码：`0` 成功；`1` 合成失败（输入文件缺失/JSON 非法/缺评分/评分非数字/difficulty 非法等）；`2` 参数个数不对。
- 失败信息写到 stderr。
- 本脚本是**纯计算**：只写输出 JSON，不改写任何持久层文件（难度反馈与完成度分由验收流程写入 `progress.md`，见 ticket 12）。

## 2. 输入文件（JSON）

```json
{
  "agent_score": 4,
  "self_score": 4,
  "difficulty": "刚好"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `agent_score` | 是 | agent 评分，1–5 的数字；超出范围自动截断到 [1, 5]。 |
| `self_score` | 是 | 学习者自评，1–5 的数字；超出范围自动截断到 [1, 5]。 |
| `difficulty` | 否 | 难度反馈，封闭集合 `"太难" \| "刚好" \| "太简单"`；缺省输出 `null`。非法值报错。 |

## 3. 输出文件（JSON）

```json
{
  "agent_score": 4,
  "self_score": 4,
  "raw": 4.0,
  "score": 4.0,
  "score_display": "4/5",
  "synthesis": "0.7 × 4 + 0.3 × 4 = 4",
  "difficulty": "刚好"
}
```

| 字段 | 说明 |
| --- | --- |
| `agent_score` / `self_score` | 回显输入（已截断）。 |
| `raw` | 未取整的合成值（输入评分按百分位折算，结果精确到百分位），如 `4.25`。 |
| `score` | **完成度分**：`raw` 四舍五入到 0.5 档，截断在 [1, 5]。 |
| `score_display` | 展示格式 `x/5`（`4/5`、`4.5/5`），与 `progress.md` 完成度格式一致。 |
| `synthesis` | 合成算式文本：`0.7 × 4 + 0.3 × 4 = 4`；取整后与 `raw` 不一致时用 `≈`（如 `0.7 × 5 + 0.3 × 3 ≈ 4.5`）。 |
| `difficulty` | 回显难度反馈；未提供时为 `null`。**独立记录，不参与合成。** |

## 4. 合成规则（7:3）

- **完成度分 = 0.7 × agent 评分 + 0.3 × 学习者自评**，先合成、后取整到 0.5 档（四舍五入），再截断在 [1, 5]。
- 输入评分同样截断在 [1, 5]（`7/6` → 按 `5/5` 合成；`-2/0` → 按 `1/1` 合成）。
- 取整示例：`4.0 → 4`；`4.3 → 4.5`；`4.7 → 4.5`；`3.6 → 3.5`；`4.25 → 4.5`（half-up，`x.25` 进到 `x.5`）。
- 输入评分先折算为百分位整数，此后全程整数运算（`7×agent + 3×self` 以 1/1000 分表示），无浮点取整边界误差。
- 完成度分的用途：`progress.md` 记录完成度；验收结果写回能力矩阵（完成度 ≥ 4 → 该知识点 +0.5，上限 5）由 ticket 05 脚本负责。

## 5. 难度反馈（独立记录）

- 取值：`太难` / `刚好` / `太简单`，封闭集合；非法值报错，防止脏数据进入 `progress.md`。
- 语义：**不参与完成度分**（同样分数配不同难度反馈，合成结果相同）；只影响后续计划难度档位（见 spec「完成度评分」）。

## 7. 用法示例（agent 流程）

1. 验收对话：学习者提交证据 → agent 逐项核查给结论（完成/部分完成/未完成 + 理由）→ 与学习者各自打分 → 调本脚本合成完成度分。
2. 输入 `agent_score` / `self_score` / `difficulty` → 拿到 `score` 与 `score_display`，展示给学习者确认（混合式验收：确认权在学习者）。
3. 确认后，验收流程把 `score_display`、`synthesis`、`difficulty` 写入当日总结（`progress.md`，ticket 12）。
