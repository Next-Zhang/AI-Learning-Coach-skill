# 每日会话开始流程契约（ticket 11）

每个学习日**新会话**开头的编排流程：**① 复习检查**——查调度表到期知识点，一问一答考察（间隔重复：通过推进档位、未通过重置回 1 天），考察得分写回掌握度；**② 随机抽查热场**——新课开头随机抽查 2 个历史知识点回顾热身（不计分、不回写）；**③ 当日网页生成**——调 `scripts/page.py` 输出单文件 HTML 执行视图；**④ 执行辅助**——按范围声明辅助当日实操，关键事实引用来源。

复习检查与写回依赖既有脚本（ticket 02/03/05/06）：`scripts/schedule.py`（查到期 `due` / 记录考察 `record`，契约见 `resources/schedule-contract.md`）、`scripts/profile.py`（`op=review` 写回能力矩阵，契约见 `resources/profile-contract.md`）、`scripts/page.py`（当日网页，契约见 `resources/page-contract.md`）、`scripts/retrieve.py`（检索层，契约见 `resources/retrieval-contract.md`）。这些脚本的输入输出格式各自见对应契约，本文档**不重复其格式**，只规定会话开头的**对话编排**如何调用它们，与各 ticket 的越界分工。

按 spec「测试 seam」：对话式流程（计划生成、验收对话等）**不设自动化 seam**，构建后通过**实际演练验证**；本文档定义对话协议本身。

---

## 1. 目标与范围

- **目的**：每个学习日新会话开头，先对抗遗忘曲线（到期知识点考察 → 得分写回），再回顾热身（随机抽查 2 个历史知识点），然后产出当日执行视图（单文件 HTML），最后在**范围声明**框内辅助当日实操——让学习者的每次学习都从「复习衔接 → 带目标执行」开始。
- **范围**：只做会话开头四件事——复习检查与考察、随机抽查热场、当日网页生成、当日执行辅助。验收/总结/网页删除属 ticket 12，复习快查文档生成与调度表 `add` 属 ticket 13，**本流程不越界**。
- **硬约束**：考察题目必须有依据（快查文档/来源，护栏「引用规范」）；考察写回（`record` + `review`）必须成对调用、同一知识点同一结果；写回属持久层修改，执行前先经学习者确认（护栏 approval）；执行辅助只做当日任务（范围约束）。

## 2. 起点与前置

- **前置**：`plan.md` 已生效（`status: active`，每日任务齐备，ticket 10）、`profile.md` 能力矩阵已建立（ticket 09）、复习调度表 `review/schedule.md` 与复习快查文档 `review/` 就位（至少覆盖已完成课程，ticket 13 起持续维护）。
- **读取**（会话开头逐一读，只读）：`plan.md`（frontmatter `goal`/`scope_covered`/`scope_excluded` + 定位当日 Day 区块）、`review/schedule.md`、`profile.md`（能力矩阵）、`progress.md`（昨日进展，供一句衔接语）。
- **开场示例**："欢迎回到 Day N（主题：…）。先复习今天的到期知识点，然后我们生成今天的执行页，开始干活。"
- **分支**（当日任务定位后判断）：
  - 调度表为空或今天无到期 → 跳过复习考察；
  - 无历史知识点（新计划首日）→ 跳过随机抽查热场；
  - 其余 → 复习考察 → 热场 → 网页 → 执行。
- 当日任务定位与 `resources/page-contract.md` §2 的 `day` 一致（`Day N` / 编号 / 日期均可），以 `plan.md` 为准。

## 3. 复习检查（到期知识点）

1. **查到期**：调 `scripts/schedule.py`，`op=due`，`today=今天` → 到期知识点列表（下次复习日 ≤ 今天，按 日期 → 知识点 排序）。
2. **展示概览**：列出到期知识点及各自「下次复习日 / 当前间隔 / 掌握度」，询问学习者开始考察（或直接开始）。
3. **逐一考察**：每个到期知识点按 §4 一问一答（每题只考一次，不连环追加）。
4. **汇总与确认**：全部考完后，展示**考察结果单**（表格：知识点 → pass/fail → 调度档位将如何推进 → 矩阵增量），请学习者确认后**统一写回**（见 §4.4，approval 护栏，批量一次确认）。
5. 写回完成后简要汇报："复习完成：N 个通过推进，M 个未通过已重置（会很快再见）。" 未通过的知识点如实提示"近期会再复习"，可在当日执行中顺手覆盖其温故内容（不展开成教学环节）。

## 4. 一问一答考察协议

### 4.1 出题（有依据、有针对）

- **依据**：优先该知识点对应的**复习快查文档**（`review/NN-主题.md`，每知识点一行：概念一句话 + 关键代码 + 常见坑 + 来源；可用 `scripts/review.py` `op=query` 按关键词/日期定位，契约见 `resources/review-contract.md`）；无快查文档 → 用该知识点相关的本地 `sources/` 资料（可先用检索层 `retrieve.py` 查）；再缺 → 用能力矩阵该知识点已学内容的代表（如当日验收证据）。**无依据不出题**（护栏「引用规范」）。
- **出题形式**：以**「常见坑」或「关键代码」**出题为主（比概念复述更能暴露遗忘），可混合概念一句话。示例：
  - 坑题："pandas 里 `df[df['x'] > 1]` 和 `df[df['x'] > 1]['col']` 连着用有什么坑？怎么避免？"（依据 review/04-… 的坑条目）
  - 代码题："写一行代码，用字典创建 Series。"
  - 概念题："变量名的命名规则是什么？"
- 出题时标明依据来源（"这道题来自你的复习卡 review/01-…"）。

### 4.2 作答

- 一问一答：agent 出题 → 学习者对话内作答（可贴文字/代码）→ 判分 → 下一题。
- **「不会/忘了」明确允许** → 记 `fail`（遗忘是真实信号，比瞎猜有价值）；**不追问、不给提示、不引导猜**。
- 考察阶段**不教学、不给答案**：答错的题不现场重讲（教学统一放当日执行）；判分依据在下一题开始前可简短说明（对照快查卡）。

### 4.3 判分（pass / fail 两档）

- `pass`：核心概念正确，或代码正确且能说出常见坑；
- `fail`：答不出（"忘了/不会"）、核心错误或概念混淆。
- **判分透明**：每题给一句判分依据（"对照你复习卡的坑：…，你答得对/差在…"）；学习者可质疑，复核后改判须说明理由。

### 4.4 得分写回（成对调用、批量确认）

全部考察结束、学习者确认**考察结果单**后，**逐知识点成对调用**（同一知识点、同一 `result` 两处同步）：

1. `scripts/schedule.py`，`op=record`，`topic`、`result=pass|fail` → 调度表推进（通过 +0.5/推进下一档 1→3→7→15→30；未通过 -0.5/重置回 1 天）；
2. `scripts/profile.py`，`op=review`，`topic`、`result`（同上）→ 能力矩阵同规则增量（+0.5 上限 5 / -0.5 下限 1）。

- **approval 护栏**：首次写回会原地改写 `review/schedule.md` 与 `profile.md`，属持久层修改，**先展示考察结果单、经学习者确认后统一写回**；多个到期知识点一次性批量确认，不逐题打扰。
- **中途退出**：未确认**不写回**（不写半成品）——到期知识点保留在原状态，下次会话重新考察。
- **一致性**：只查调度表决定考什么（性能护栏，不扫 `review/` 全部文档）；写回后 `schedule.md` 掌握度与 `profile.md` 能力矩阵保持一致（矩阵为权威值，见 `resources/data-formats.md` §6）。

## 5. 随机抽查热场（新课开头）

1. **时机**：复习考察（或跳过）之后、进入当日网页之前；仅当日任务有**新课**内容时的开头。
2. **对象**：已完成学习的历史知识点中**非到期**的（不与刚考过的重复）；随机抽 **2 个**。候选 = 已学（能力矩阵中「来源」为验收/复习、或明确已学习的非到期知识点），且不在今日 `due` 列表中的知识点——**未学的矩阵行（仅摸底建立、未学未考）不得纳入热场**（避免把新课知识点当历史抽）。
3. **随机方式**：agent 从候选列表随机抽取（如打乱后取前 2），不需要面向用户解释随机性。
4. **形式**：快问快答式回顾（概念一句话 / 代码认读 / 一句坑提醒），每题 **≤ 1 回合**，不展开、不教学。
5. **不计分不回写**：热场 = 唤醒记忆，**不判分、不写回掌握度、不推进调度表**（区别于 §4 到期考察；避免把非到期知识的噪音写进数据）。
6. **候选不足**：候选 < 2 → 抽可用数量；候选为 0（如新计划第 2 天，全部历史知识点都在到期考察中）→ **跳过并说明**，不强行从到期知识点里凑。
7. **答不对**：温和提示复习方向（指向对应快查文档/来源），立即继续，不打断当日节奏。

## 6. 当日网页生成

1. **检索当日知识点**：对当日任务「知识点」调 `scripts/retrieve.py`，本地相关命中不足时允许一次 `web_search` 补充（阈值与并入规则见 `resources/retrieval-contract.md`）。
2. **提炼 knowledge**：把检索结果提炼为「概念 + 示例」条目（`page.py` 的 `knowledge` 输入，契约见 `resources/page-contract.md` §2）；不提炼时脚本会读当日任务来源正文兜底。
3. **生成网页**：调 `scripts/page.py`，输入 `plan_path` + `day`（当日任务标识）+ （可选）`knowledge` → 输出 HTML 到系统临时目录（可 `output_dir` 覆盖）；拿到 `html_path`。
4. **呈现**：把网页交付给学习者——说明可双击离线打开、可勾选目标，当日执行用它做参照；如环境支持，直接打开/展示路径。
5. **不删除**：网页在验收完成、当日总结写入后由 ticket 12 流程提出删除（本流程只生成）。

## 7. 执行辅助（范围约束、来源引用、辅助实操）

- **边界 = 当日任务 + 范围声明**：只教 `plan.md` 当日 Day 区块的内容，且严格在 frontmatter `scope_covered` 内；`scope_excluded` 绝不教；任何偏离当日任务的内容（加戏、超前、跑偏）一律不做，发现偏离立即拉回（护栏「范围约束」）。
- **关键事实引用来源**：当日涉及的关键事实、语法、方法名给出来源（检索层 `retrieve.py` 查 `sources/`，必要时 `web_search`），不编造（护栏「引用规范」）。
- **辅助实操循环**：给任务/小提示 → 学习者动手（在自己的环境写代码）→ 学习者贴结果/报错 → agent 反馈纠错（示范代码 + 讲清原因）→ 再动手。逐步放手，鼓励自己完成。
- **收敛与上限**：整体会话步骤遵守 30 步上限（护栏「运行参数上限」）；接近上限时收敛任务、提示"明日继续"，进入收尾。
- **收尾**：当日任务完成后，进入「反馈与验收」流程（ticket 12）——本流程不越界。

## 8. 边界与护栏

- **ticket 分工**：不写 `progress.md`（ticket 12）、不生成复习快查文档/调度表 `add`（ticket 13）、不做验收与当日网页删除（ticket 12）；复习考察只用于到期知识点，热场不计分。
- **写回一致性**：`schedule.py record` 与 `profile.py review` 必须同一知识点、同一 `result` **成对**调用；同步规则与「矩阵是权威值」见 §4.4 与 `resources/data-formats.md` §6。
- **approval**：`schedule.md` / `profile.md` 写回属持久层修改，写前先经学习者确认（考察结果单批量确认一次）；**不确认不写回**。
- **引用规范**：考察题、当日知识、执行辅助的关键事实都必须有依据（快查文档/来源）；无依据不出题、不讲。
- **范围约束**：执行只做当日任务 + `scope_covered`；`scope_excluded` 不教。
- **防空转**：到期知识点逐题有限（有穷列表）；热场 2 题封顶；会话步骤上限 30（护栏）。

## 9. 验证方式

- 本流程为对话式流程，按 spec「测试 seam」**不设自动化 seam**，构建后通过**实际演练验证**。演练产物存于 `.scratch/python-coach/rehearsal-11/`。
- **演练记录（2026-08-25，ticket 11 构建时，Day 5 早晨场景）**：前置数据（`rehearsal-11/data/`）模拟「Day 1–4 已完成、其后各课知识点已按 ticket 13 纳入调度表」的 Day 5 晨间状态——调度表 6 知识点（变量/条件/函数/Series/DataFrame/数据读取与筛选，各带档位），当日 Day 5 = 08-25。
  - **复习检查**：`schedule.py op=due`（today=2026-08-25）→ 到期 `变量与数据类型`（2.5/5，3 天档，到期 08-25）与 `数据读取与筛选`（3/5，1 天档，到期 08-25），其余 4 个非到期 → 展示概览后逐一考察（**转写摘录**见 `rehearsal-log.md`）。
  - **一问一答考察**：变量题（依据 `review/01-variables-conditions.md`）学习者答对 → `pass`；读取筛选题（依据 `review/04-reading-filtering.md`）学习者答错 → `fail`。汇总考察结果单，学习者确认后成对写回：`schedule.py record`（两个知识点）+ `profile.py review`（两个知识点），脚本均退出码 0 → 调度表推进（变量 3.0/7 天/下次 09-01；读取筛选 2.5/重置 1 天/下次 08-26），矩阵同步（变量 3.0、读取筛选 2.5）。
  - **随机抽查热场**：候选 = 非到期历史 4 个（条件/函数/Series/DataFrame），随机抽 2 个（函数、pandas.Series）→ 快问快答回顾，不计分不回写（**转写摘录**见 `rehearsal-log.md`）。
  - **当日网页生成**：检索层检索「Excel 读写」→ 提炼 knowledge → `page.py` 生成 `day-5-2026-08-25.html`（四区块齐全：知识/链路/目标含勾选/来源链接），输出 JSON 字段正确。
  - **执行辅助**：按范围声明引导 Day 5 实操（read_excel/to_excel/sheet 参数），给出来源链接；当日不动 `progress.md`、不生成复习快查（留给 ticket 12/13）。
  - 产物：`data/`（before 副本 `data-before/` + 演练后的工作数据）、`due.out.json`、`record-*.in/out.json`、`review-*.in/out.json`、`page-out/`（HTML + json）、`rehearsal-log.md`（完整转写与脚本记录）。
- 写回路径的自动化测试另由 `scripts/test_schedule.py`（ticket 03）与 `scripts/test_profile.py`（ticket 05）兜底；网页生成由 `scripts/test_page.py`（ticket 06）兜底。
