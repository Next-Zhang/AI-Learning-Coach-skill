# 目标澄清与范围声明流程契约（ticket 08）

起步流程第 2 步的对话式目标澄清：学习者用一句话说出「想用 Python 做什么」的具体目标 → agent 圈定所需子领域 → 生成显式**范围声明**（覆盖什么、不涉及什么）→ 写入 `plan.md` 草案。范围声明是后续**检索源选择**（摸底测试与计划生成的检索范围）、**验证评审对象**（计划三验证）与**失控防护锚点**（护栏「范围约束」以 `plan.md` 为准）的共同依据。

按 spec「测试 seam」：对话式流程（计划生成等）**不设自动化 seam**，构建后通过实际演练验证；本文档定义对话协议本身。写入的 `plan.md` 草案格式遵循 `resources/data-formats.md` §1 与 `templates/plan.md`（`page.py` 已按该 frontmatter 格式解析并有自动化测试，见 `resources/page-contract.md` §5），本文档不再重复数据格式，只规定对话层如何澄清、圈定、确认并写入草案。

---

## 1. 目标与范围

- **目的**：把学习者的一句话目标澄清到「具体、可执行」的程度 → 圈定实现该目标所需的 Python 子领域 → 生成显式范围声明（覆盖/不涉及），写入 `plan.md` 草案，为摸底测试（ticket 09）、计划生成与三验证（ticket 10）提供输入。
- **范围**：只做目标澄清 + 子领域圈定 + 范围声明 + 写 `plan.md` 草案。摸底测试（ticket 09）、计划生成与三验证（ticket 10）属后续步骤，**本流程不越界**。
- **硬约束**：目标必须由学习者自己说清，agent 只澄清、不代拟；覆盖/不涉及两份清单在落盘前必须经学习者逐条确认；写入 `plan.md` 属持久层修改，执行前先经学习者确认（护栏 approval）。

## 2. 起点：profile.md 的「学习目标」

- 起步流程第 1 步（onboarding 问卷，ticket 07）已收集「学习目标」答案并写入 `profile.md`。本流程**以此答案为起点**，先读 `profile.md` 的「学习目标」展示给学习者，而不是从零问起。
- 开场示例："你在问卷里说『…』。接下来我们把它说具体，并划出这次学习覆盖、不涉及的范围。"
- 若澄清后最终目标与画像表述有实质差异（不只是措辞），向学习者说明，并询问是否重跑 onboarding 问卷（`profile.py` `op=onboarding`，8 题重答）同步更新画像；学习者拒绝则保留画像原值，`plan.md` 的 `goal` 以澄清后的最终目标为准（计划锚点以 `plan.md` 为权威，见 `data-formats.md` §1）。

## 3. 目标澄清对话（一句话目标）

1. **展示起点**：读出 `profile.md`「学习目标」，请学习者确认或修正："这就是你想用 Python 做的事吗？可以再具体一点。"
2. **具体性检查**：满足以下三条即视为具体：
   - 有明确应用场景（做什么、处理什么/产出什么），如"用 Python 处理 Excel 报表并做数据分析"；
   - 能据此判断该学哪些子领域（agent 能否从目标推出 2 个以上所需子领域）；
   - 一句话能说清（建议 ≤ 50 字，可含场景+产出）。
3. **模糊回答**（如"学 Python"、"想变厉害"、"把数据分析学好"）→ 追问澄清，用引导示例启发："具体用 Python 做什么？处理哪类数据 / 搭建什么 / 自动化什么？" 例如："是想处理 Excel 报表，还是爬网页数据，还是做图表？"
4. **追问上限**：同一目标的澄清追问**不超过 3 轮**；3 轮后仍未具体 → 暂停并说明"目标太模糊将无法圈定范围"，请学习者换个说法再继续，**不无限追问**（护栏「运行参数上限」）。
5. **不代拟**：可给示例启发，但最终目标句子必须由学习者确认后定稿。

## 4. 子领域圈定

确认目标后，agent 圈定实现该目标所需的 Python 子领域（短名词短语，如 `语法基础`、`数据结构`、`函数与模块`、`面向对象`、`文件/Excel 处理`、`数据分析（pandas）`、`数据可视化`、`网络爬虫`、`Web 开发`、`自动化脚本`、`测试`、`数据库`、`机器学习` 等）。

**圈定逻辑（agent 判断，逐条给学习者理由）：**

1. **必需子领域**：完成该目标"缺了就没法学"的领域。如"处理 Excel 报表并做数据分析" → `数据分析（pandas）` + `Excel 处理` + `数据可视化`。
2. **必要前置**：`语法基础`、`数据结构` 等前置领域按学习者已有水平裁剪——参照 `profile.md` 的「Python 水平自评（1–5）」：自评 ≤ 2 时前置领域必须保留在覆盖内（避免计划悬空），自评 ≥ 4 时可少圈或不圈。
3. **数量约束**：覆盖子领域 **3–7 个**；超出时合并同类项（如 `数据分析` 与 `pandas` 合并）或聚焦核心，避免范围膨胀。
4. **检索查证**：可先用检索层（`scripts/retrieve.py`）查证每个圈定子领域在 `sources/` 是否有对应资料（范围声明是检索源选择锚点）；资料缺失的子领域如实标注"需补充资料"，**不悄悄取消也不悄悄保留**。
5. **学习者确认**：逐条展示"为什么圈这个"（一两句话理由），学习者可增删改，改完重新确认。

## 5. 范围声明生成（覆盖 / 不涉及）

- 范围声明 = `scope_covered`（覆盖）+ `scope_excluded`（不涉及），来自 §4 确认的清单。
- **`scope_excluded` 圈定逻辑**：与目标相邻、学习者可能误以为会学、但本计划明确不教的领域。如目标 = 数据分析 → 排除 `Web 框架`、`网络爬虫`、`机器学习`。数量 **1–3 个**为宜，宁缺毋滥——只排除"容易被误期待"的领域，不堆砌。
- **展示格式**（落盘前给学习者看）：
  - 覆盖：语法基础（前置）、数据分析（pandas）、Excel 处理、数据可视化
  - 不涉及：Web 框架、网络爬虫
- **学习者确认**：明确询问"这个范围对吗？有想加进范围或移出范围的吗？"——范围声明是后续失控防护锚点，**学习者确认后才可落盘**。

## 6. 写入 plan.md 草案

确认后写入 `plan.md` 草案，格式严格遵循 `resources/data-formats.md` §1 与 `templates/plan.md`：

```markdown
---
goal: 用 Python 处理 Excel 报表并做数据分析
scope_covered: [语法基础, 数据分析（pandas）, Excel 处理, 数据可视化]
scope_excluded: [Web 框架, 网络爬虫]
status: draft
created: 2026-08-20
updated: 2026-08-20
---

# 学习计划

## 每日任务

（草案：目标与范围声明已确认；每日任务清单由计划生成阶段填充，落盘时 status 置为 active。）
```

**约定：**

- `goal` 为 §3 定稿的一句话目标；`scope_covered` / `scope_excluded` 为 §4–§5 确认的清单。数组格式 `[a, b]`，**数组内用英文逗号（`,`）分隔**（与 `page.py` 的 `_parse_list` 解析规则一致，见 `resources/page-contract.md` §5），支持裸字符串或数组。
- `status: draft` 表示计划为草案（本阶段写入）；计划落盘（ticket 10 评审通过）时置为 `active`。`created`/`updated` 取当天日期 `YYYY-MM-DD`。
- 正文只保留 `# 学习计划` 与空的 `## 每日任务`（占位说明），**不写任何 Day 区块**（每日任务属 ticket 10）。
- **覆盖语义**：`plan.md` 已存在（学习者重走起步流程）时，只改写 frontmatter 的 `goal` / `scope_covered` / `scope_excluded` / `status` / `updated`，正文（每日任务）保持原样不动——若原计划 `status` 为 `active`（已落盘），先向学习者说明"重走起步会把已落盘计划降回草案，每日任务保留但需按新范围重新生成"，确认后才写。
- **approval 护栏**：`plan.md` 属持久层六件套，写入/改写前先经学习者确认（SKILL.md 护栏 approval）。

## 7. 边界与护栏

- 不越过本流程：不生成摸底题（ticket 09）、不生成每日任务/三验证（ticket 10）、不新增或改写 `sources/` 资料。
- 子领域圈定与范围声明由 agent 判断，但**覆盖/不涉及两份清单必须经学习者确认**；不得静默增删。
- 目标必须来自学习者；agent 只澄清、不代拟、不推测默认目标。
- 澄清追问轮次上限 3 轮（护栏「运行参数上限」）。
- 写入 `plan.md` 需学习者确认（护栏 approval）；中途退出时**不写半成品**——未确认完整范围声明不落盘草案。

## 8. 验证方式

- 本流程为对话式流程，按 spec「测试 seam」**不设自动化 seam**，构建后通过**实际演练验证**：模拟学习者澄清对话（含一次模糊目标追问）→ 圈定/确认范围 → 写入草案 → 检查 `plan.md` 原文（frontmatter `goal`/`scope_covered`/`scope_excluded`/`status: draft` + 空每日任务）→ 按 `page.py` 的 frontmatter 解析规则（`resources/page-contract.md` §5）人工核对可解析。
- **演练记录（2026-08-20，ticket 08 构建时）**：模拟对话——起点为画像「学习目标：用 Python 做数据分析」（先答模糊，被追问"具体处理什么数据？"后澄清为"用 Python 处理 Excel 报表并做数据分析"）→ 圈定覆盖 `语法基础`（前置，自评 2 故保留）、`数据分析（pandas）`、`Excel 处理`、`数据可视化`（学习者确认）→ 排除 `Web 框架`、`网络爬虫` → 学习者确认范围 → 写入 `plan.md` 草案（`status: draft`，空每日任务）→ 检查原文：frontmatter `goal`/`scope_covered`/`scope_excluded`/`status` 齐全（含 `created`/`updated`）、正文无 Day 区块，符合 §6 预期；草案文件经 `page.py` frontmatter 解析规则核对可解析（`goal` 字符串、`scope_covered`/`scope_excluded` 数组）。
- 草案的格式兼容性（frontmatter 解析）另有 `scripts/test_page.py` 的 plan.md 解析测试兜底（`resources/page-contract.md` §6）。
