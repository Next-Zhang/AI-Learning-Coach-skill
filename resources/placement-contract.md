# 摸底测试流程契约（ticket 09）

起步流程第 3 步的对话式摸底测试：**范围驱动**（题目只出自 `plan.md` 范围声明 `scope_covered`）的 15–20 题（选择题 10–12 + 简答/实操 5–8，难度梯度 1–5），**混合式作答**（选择题对话内选、简答/实操贴文字或代码），agent 对照**评分标准**判分，按**难度加权公式**合成能力矩阵（领域 → 子领域 → 知识点/能力，知识点行水平分 1–5、能力行前置状态二值），另加**前置能力评估题组**（对能力行快速评估），经 `scripts/profile.py`（`op=placement`）写入 `profile.md`。能力矩阵是计划生成（ticket 10）的适配性输入，前置状态是计划前置校验（决策 3/13/14）的依据。

按 spec「测试 seam」：对话式流程（计划生成、验收对话等）**不设自动化 seam**，构建后通过实际演练验证；本文档定义对话协议本身。矩阵写入路径由 `scripts/profile.py` 提供并有自动化测试（ticket 05 的脚本，新增 `op=placement`，见 `resources/profile-contract.md` §7），本文档不再重复其输入输出格式，只规定对话层如何出题、作答、判分、合成并调用它。

---

## 1. 目标与范围

- **目的**：在计划生成前，用范围声明内各知识点的少量题目测出学习者的真实水平，产出能力矩阵（领域 → 子领域 → 知识点/能力）写入 `profile.md`，作为计划适配性（深度、份量、难度档位）与前置校验（知识点 ≥ 3 具备、能力 具备|未具备）的输入。
- **范围**：只做摸底测试本身——出题 → 作答 → 判分 → 合成 → 写矩阵（含前置能力评估题组）。计划生成与三验证是 ticket 10、每日执行/验收是 ticket 11/12、复习调度是 ticket 03/13，**本流程不越界**。
- **硬约束**：题目只出自 `scope_covered`（`scope_excluded` 不考）；题量/题型/难度约束固定（§3）；判分必须对照出题时写定的参考答案/评分要点；写 `profile.md` 属持久层修改，执行前先经学习者确认（护栏 approval）。

## 2. 起点与前置

- **前置**：`profile.md` 已建立（ticket 07 onboarding）、`plan.md` 草案已落盘（ticket 08 目标澄清与范围声明）。
- **起点**：读 `plan.md` frontmatter 的 `scope_covered` 作为出题范围；可选参考 `profile.md` 的「Python 水平自评（1–5）」微调难度重心（自评低 → 低档题占比高，但不得突破 §3 的难度覆盖约束）。
- 开场示例："接下来做一个 15–20 题的摸底测试，摸清你当前的水平，之后生成的计划会更贴合你。题目都来自你确认的范围（列出 `scope_covered`），答不出的题直接说'不会'，不要猜。"

## 3. 题目生成（范围驱动、难度梯度）

### 3.1 题目集硬约束

| 约束 | 取值 |
| --- | --- |
| 总题量 | **15–20 题** |
| 选择题 | **10–12 题**（单选，选项 3–5 个） |
| 简答/实操 | **5–8 题**（简答贴文字答案；实操贴代码/运行结果） |
| 范围覆盖 | `scope_covered` 每个子领域**至少 2 题**、每个知识点**至少 1 题**；题目知识点落在子领域内（单题知识点的水平分按该题加权分定级，噪声由计划生成时综合判断，见 ticket 10） |
| 难度梯度 | 题集整体覆盖**难度 1–5 五档**（每档至少 1 题）；低档题多于高档题（约金字塔分布） |

难度档位语义：**1** = 概念识别（看到能认出来）；**2** = 简单用法（知道怎么用）；**3** = 常规应用（能独立写常见代码）；**4** = 综合应用（多步/组合/排错）；**5** = 进阶/易错点（边缘情况、性能、深层机制）。

### 3.2 每题元数据（出题时一次写定，判分不临时发挥）

| 字段 | 说明 |
| --- | --- |
| 题号 | `Q1`–`Q20` 连续编号 |
| 类型 | `选择` \| `简答` \| `实操` |
| 知识点 | 题目测的知识点名，粒度与 `plan.md` 每日任务「知识点」一致（如 `pandas.Series`）；合成时按它聚合成矩阵行 |
| 子领域 | 该知识点所属的 `scope_covered` 子领域（范围驱动锚点） |
| 难度 | 1–5 |
| 题干 | 问题描述；选择题含选项（3–5 个，标注编号 A/B/C/D） |
| 参考答案 | 选择题的标准答案；简答/实操题的**评分要点**（2–4 条，判分对照） |
| 依据 | 题目与答案的依据来源（`sources/` 检索或公认教材知识） |

### 3.3 生成规则

- **范围驱动**：只考 `scope_covered` 内知识点；`scope_excluded` 领域一律不出题。发现题目跑出范围立即替换。
- **内容依据**：题目、参考答案/评分要点须有依据（可先用检索层 `scripts/retrieve.py` 查 `sources/`）；无依据的题目不采用（护栏「引用规范」）。
- **难度相符**：题目标注难度须与内容实际难度相符——简单题不刁钻（不设文字陷阱），难题不超纲（不考范围外机制）。
- **生成后先展示概览**：题数、各子领域题量、难度分布，请学习者确认后开始作答（学习者可要求减少到下限 15 题）。

### 3.4 前置能力评估题组（能力行，决策 2/13）

- **目的**：能力矩阵除「知识点」行外还有独立「前置能力」层（类型 = 能力，如 Python 工程组织、OOP 素养、ABM 建模理解等）——它没有水平分，只有二值前置状态（`具备 | 未具备`），是计划前置校验与补前置天的判定依据。
- **能力行清单**：出题前从目标与范围推断可能的前置能力（与范围子领域对应的工程/建模素养，通常 2–5 个）；每个能力行**一组 2–3 问快速评估**（判断/简述/小实操），题目有依据、判分有要点（与 §3.2 同规范）。
- **作答与判分**：与知识题同会话、同批次作答（可放在知识题之后）；「不会/跳过」→ 未具备；判分对照要点给二值结论（`具备 | 未具备`），判分透明可质疑。
- **题量**：不占 §3.1 的 15–20 题名额（额外小组），总会话步骤仍守运行参数上限。
- **写入**：随 `op=placement` 的 `results` 一并写入矩阵——能力行 `{topic, type: "能力", pre_status: "具备"|"未具备", domain?, subdomain?}`（水平分 = —，见 `resources/profile-contract.md` §2）。

## 4. 混合式作答流程

1. **逐题进行**：按题号顺序一次一题。选择题在对话内直接选（"选 B"或"B"或选项文字均可）；简答/实操请学习者贴文字或代码（代码用 ``` 代码块包裹，可多行）。
2. **「不会/跳过」**：明确允许。学习者说"不会/跳过/这道不会"→ 该题按 **0 分**记录（这是真实水平信号，比瞎猜有价值）；**不追问、不给提示、不引导猜答案**。
3. **不代答**：作答阶段 agent 不给答案、不给解题提示、不评价对错（判分统一放在作答结束后）；学习者问"对不对"只回答"先做完，最后统一判分"。
4. **回看与修改**：学习者可随时要求"回看第 N 题"/"重答第 N 题"，只重问该题并覆盖原答案，其余题不动。
5. **记录**：每题只记学习者明确给出的答案或"跳过"；对话中的解释、思考过程不写入记录（判分只看最终答案）。
6. **题量固定**：15–20 题硬约束，不临时加题；整体在会话步骤上限（护栏「运行参数上限」）内完成。

## 5. 评分标准与判分

作答结束后统一判分（学习者可要求逐题判分展示）：

- **选择题**：与参考答案一致 → `1` 分；不一致 → `0` 分（无部分分）。
- **简答/实操**：对照出题时写定的**评分要点**逐条给分（每条 `0` / `0.5` / `1` 档），要点得分取**均值** → `0–1` 分。实操题评分要点含：能否运行、是否达到目标行为、关键点（如缩进/API 名称）是否用对。
- **跳过/不会** → `0` 分。
- **判分者**：agent。判分依据只有出题时写定的参考答案/评分要点，不引入题外标准；拿不准时回到检索层核对依据，不凭印象判分。
- **判分透明**：简答/实操逐条展示要点得分（"要点 1：0.5，要点 2：0……"）；学习者可质疑，agent 复核后改分须说明理由。
- **判分结果**：每题得分 `s_i ∈ [0, 1]`（保留 0.5 档），连同题号/知识点/难度记录，作为合成输入。

## 6. 能力矩阵合成与写入

### 6.1 合成公式（难度加权）

- 每题权重 `w_i` = 题目难度（1–5）——难题答对拉高、简单题答错拉低。
- 每个知识点的水平分：

  ```
  level = round0.5( 5 × Σ(w_i × s_i) / Σw_i )，再截断到 [1, 5]
  ```

  其中 `s_i` 为该知识点各题的得分（0–1），`w_i` 为对应难度；`round0.5` 为半向上舍入到 0.5 档（2.25 → 2.5，2.75 → 3.0）。知识点内无题 → 不写入矩阵（出题约束保证每知识点 ≥ 1 题，正常不会发生）。
- **语义**：全对 ≈ 5，全错/全跳过 ≈ 1（下限 1，与矩阵水平分区间一致）。
- **能力行不参与本公式**：前置能力评估（§3.4）直接给二值结论（具备/未具备），无水平分。

### 6.2 展示与确认

- 合成后展示能力矩阵（领域/子领域/知识点/类型/水平分/前置状态）与判分摘要（每题得分），请学习者确认或质疑；确认后才写入。

### 6.3 写入 profile.md（op=placement）

调用 `scripts/profile.py`，`op=placement`，`results` 为合成后的知识点水平分数组 + 前置能力评估能力行：

```bash
python scripts/profile.py <input.json> <output.json>
```

```json
{
  "op": "placement",
  "date": "2026-08-20",
  "results": [
    { "topic": "pandas.Series", "type": "知识点", "score": 1.5, "domain": "数据分析", "subdomain": "pandas" },
    { "topic": "pandas.DataFrame", "type": "知识点", "score": 1, "domain": "数据分析", "subdomain": "pandas" },
    { "topic": "Python 工程组织", "type": "能力", "pre_status": "未具备", "domain": "工程", "subdomain": "工程素养" }
  ]
}
```

- 输入输出格式见 `resources/profile-contract.md` §2–§3，用法与退出码见 §1；`date` 缺省即可，**`profile_path` 一律显式传 `.python-coach/state/profile.md`**（六件套路径约定见 `resources/data-formats.md` 开头「工作区目录结构」）。
- **语义**：`results` 内行整体按新值写入（来源「摸底测试」、日期 = date）——知识点行写水平分、能力行写前置状态；不在 `results` 中的既有矩阵行保留；画像文件不存在时自动创建（与 onboarding 相同）；增量记录追加一条「摸底测试 → 初始矩阵」。**重走起步重新摸底时**：`results` 内行会被**重置**为新摸底结果（覆盖该行此前的验收/复习增量或前置状态；历史仍保留在增量记录中）——写前须明确告知学习者这一语义，经确认后才写（护栏 approval）。
- **approval 护栏**：`profile.py` 会**原地改写** `profile.md`，属持久层修改，执行前先经学习者确认（SKILL.md 护栏 approval）。
- **写入后**：简述矩阵已建立（可列出知识点与能力行数量），进入起步流程下一步（ticket 10 计划生成与三验证，前置缺口将由计划阶段补前置天处置，见 `resources/plan-contract.md` §3.1）。

## 7. 边界与护栏

- 不越过本流程：不生成每日计划（ticket 10）、不写 `progress.md`（ticket 12）、不更新复习调度表（ticket 03/13）、不新增或改写 `sources/` 资料。
- 范围驱动：题目只出自 `scope_covered`；`scope_excluded` 领域不考；判分不超出范围外知识。
- 不代答、不提示：作答阶段 agent 不给答案或提示；答不出按 0 分记，不引导猜答案。
- 判分透明：简答/实操逐条给要点得分；学习者质疑时复核，改分说明理由。
- 题量固定：15–20 题硬约束；不临时加题、不删题凑数。
- 中途退出：未完成判分/未确认合成结果**不写矩阵**（不写半成品）；下次可重新开始摸底。
- **过程文件清理**（目录与时机见 `resources/data-formats.md`「工作区目录结构」）：摸底过程记录（题目、作答、判分记录）与 `profile.py op=placement` 的 in/out JSON 放 `.python-coach/tmp/`，**起步完成即清**。清理为 agent 内部动作，不需逐条向学习者确认。

## 8. 验证方式

- 本流程为对话式流程，按 spec「测试 seam」**不设自动化 seam**，构建后经实际演练验证：模拟出题（范围驱动、难度梯度）→ 混合式作答（含一次"不会"跳过、一次简答、一次实操）→ 对照评分标准判分 → 难度加权合成 → `profile.py op=placement` 写矩阵 → 检查 `profile.md` 原文（初始矩阵行来源「摸底测试」+ 增量记录）。
- **演练记录（2026-08-20，ticket 09 构建时）**：范围四子领域出题 18 题（选择 10 + 简答 4 + 实操 4、难度 1–5 全覆盖）→ 混合式作答（含"不会"跳过、简答部分给分、实操缺行统计）→ 按要点判分合成 10 知识点水平分 → 学习者确认 → `profile.py op=placement` 写矩阵退出码 0 → 检查 `profile.md` 原文符合 §6 预期。旧演练实体产物已随版本清理。
- **前置能力评估（2026-08 修订批次 2 新增）**：在知识题组后加 2–5 个能力行各 2–3 问快速评估，判二值结论 → 随 `op=placement` 以能力行写入矩阵（`type: "能力"`、`pre_status`、水平分 = —）。矩阵写入路径的自动化测试见 `scripts/test_profile.py` 的 `PlacementTest`（ticket 09 + 批次 2 扩展）：创建画像初始化矩阵（含能力行）/ 覆盖既有行保留其余 / 0.5 舍入与 [1,5] 截断 / 能力行缺 pre_status 与非法 type 报错 / upsert 保留能力行 / 旧 4 列画像容错 / 重复知识点与非法输入报错 / CLI 退出码。
