# 摸底测试流程契约（ticket 09）

起步流程第 3 步的对话式摸底测试：**范围驱动**（题目只出自 `plan.md` 范围声明 `scope_covered`）的 15–20 题（选择题 10–12 + 简答/实操 5–8，难度梯度 1–5），**混合式作答**（选择题对话内选、简答/实操贴文字或代码），agent 对照**评分标准**判分，按**难度加权公式**合成能力矩阵（知识点 × 水平分 1–5），经 `scripts/profile.py`（`op=placement`）写入 `profile.md`。能力矩阵是计划生成（ticket 10）的适配性输入。

按 spec「测试 seam」：对话式流程（计划生成、验收对话等）**不设自动化 seam**，构建后通过实际演练验证；本文档定义对话协议本身。矩阵写入路径由 `scripts/profile.py` 提供并有自动化测试（ticket 05 的脚本，新增 `op=placement`，见 `resources/profile-contract.md` §7），本文档不再重复其输入输出格式，只规定对话层如何出题、作答、判分、合成并调用它。

---

## 1. 目标与范围

- **目的**：在计划生成前，用范围声明内各知识点的少量题目测出学习者的真实水平，产出能力矩阵（知识点 × 水平分 1–5）写入 `profile.md`，作为计划适配性（深度、份量、难度档位）的输入。
- **范围**：只做摸底测试本身——出题 → 作答 → 判分 → 合成 → 写矩阵。计划生成与三验证是 ticket 10、每日执行/验收是 ticket 11/12、复习调度是 ticket 03/13，**本流程不越界**。
- **硬约束**：题目只出自 `scope_covered`（`scope_excluded` 不考）；题量/题型/难度约束固定（§3）；判分必须对照出题时写定的参考答案/评分要点；写 `profile.md` 属持久层修改，执行前先经学习者确认（护栏 approval）。

## 2. 起点与前置

- **前置**：`profile.md` 已建立（ticket 07 onboarding）、`plan.md` 草案已落盘（ticket 08 目标澄清与范围声明）。
- **起点**：读 `plan.md` frontmatter 的 `scope_covered` 作为出题范围；可选参考 `profile.md` 的「Python 水平自评（1–5）」微调难度重心（自评低 → 低档题占比高，但不得突破 §3 的难度覆盖约束）。
- 开场示例："接下来做一个 15–20 题的摸底测试，摸清你当前的水平，之后生成的计划会更贴合你。题目都来自你确认的范围（列出 `scope_covered`），答不出的题直接说'不会'，不要猜。"

## 3. 题目生成（范围驱动、难度梯度）

### 3.1 题目集硬约束

| 约束 | 取值 |
| --- | --- |
| 总题量 | **15–20 题** |
| 选择题 | **10–12 题**（单选，选项 3–5 个） |
| 简答/实操 | **5–8 题**（简答贴文字答案；实操贴代码/运行结果） |
| 范围覆盖 | `scope_covered` 每个子领域**至少 2 题**、每个知识点**至少 1 题**；题目知识点落在子领域内（单题知识点的水平分按该题加权分定级，噪声由计划生成时综合判断，见 ticket 10） |
| 难度梯度 | 题集整体覆盖**难度 1–5 五档**（每档至少 1 题）；低档题多于高档题（约金字塔分布） |

难度档位语义：**1** = 概念识别（看到能认出来）；**2** = 简单用法（知道怎么用）；**3** = 常规应用（能独立写常见代码）；**4** = 综合应用（多步/组合/排错）；**5** = 进阶/易错点（边缘情况、性能、深层机制）。

### 3.2 每题元数据（出题时一次写定，判分不临时发挥）

| 字段 | 说明 |
| --- | --- |
| 题号 | `Q1`–`Q20` 连续编号 |
| 类型 | `选择` \| `简答` \| `实操` |
| 知识点 | 题目测的知识点名，粒度与 `plan.md` 每日任务「知识点」一致（如 `pandas.Series`）；合成时按它聚合成矩阵行 |
| 子领域 | 该知识点所属的 `scope_covered` 子领域（范围驱动锚点） |
| 难度 | 1–5 |
| 题干 | 问题描述；选择题含选项（3–5 个，标注编号 A/B/C/D） |
| 参考答案 | 选择题的标准答案；简答/实操题的**评分要点**（2–4 条，判分对照） |
| 依据 | 题目与答案的依据来源（`sources/` 检索或公认教材知识） |

### 3.3 生成规则

- **范围驱动**：只考 `scope_covered` 内知识点；`scope_excluded` 领域一律不出题。发现题目跑出范围立即替换。
- **内容依据**：题目、参考答案/评分要点须有依据（可先用检索层 `scripts/retrieve.py` 查 `sources/`）；无依据的题目不采用（护栏「引用规范」）。
- **难度相符**：题目标注难度须与内容实际难度相符——简单题不刁钻（不设文字陷阱），难题不超纲（不考范围外机制）。
- **生成后先展示概览**：题数、各子领域题量、难度分布，请学习者确认后开始作答（学习者可要求减少到下限 15 题）。

## 4. 混合式作答流程

1. **逐题进行**：按题号顺序一次一题。选择题在对话内直接选（"选 B"或"B"或选项文字均可）；简答/实操请学习者贴文字或代码（代码用 ``` 代码块包裹，可多行）。
2. **「不会/跳过」**：明确允许。学习者说"不会/跳过/这道不会"→ 该题按 **0 分**记录（这是真实水平信号，比瞎猜有价值）；**不追问、不给提示、不引导猜答案**。
3. **不代答**：作答阶段 agent 不给答案、不给解题提示、不评价对错（判分统一放在作答结束后）；学习者问"对不对"只回答"先做完，最后统一判分"。
4. **回看与修改**：学习者可随时要求"回看第 N 题"/"重答第 N 题"，只重问该题并覆盖原答案，其余题不动。
5. **记录**：每题只记学习者明确给出的答案或"跳过"；对话中的解释、思考过程不写入记录（判分只看最终答案）。
6. **题量固定**：15–20 题硬约束，不临时加题；整体在会话步骤上限（护栏「运行参数上限」）内完成。

## 5. 评分标准与判分

作答结束后统一判分（学习者可要求逐题判分展示）：

- **选择题**：与参考答案一致 → `1` 分；不一致 → `0` 分（无部分分）。
- **简答/实操**：对照出题时写定的**评分要点**逐条给分（每条 `0` / `0.5` / `1` 档），要点得分取**均值** → `0–1` 分。实操题评分要点含：能否运行、是否达到目标行为、关键点（如缩进/API 名称）是否用对。
- **跳过/不会** → `0` 分。
- **判分者**：agent。判分依据只有出题时写定的参考答案/评分要点，不引入题外标准；拿不准时回到检索层核对依据，不凭印象判分。
- **判分透明**：简答/实操逐条展示要点得分（"要点 1：0.5，要点 2：0……"）；学习者可质疑，agent 复核后改分须说明理由。
- **判分结果**：每题得分 `s_i ∈ [0, 1]`（保留 0.5 档），连同题号/知识点/难度记录，作为合成输入。

## 6. 能力矩阵合成与写入

### 6.1 合成公式（难度加权）

- 每题权重 `w_i` = 题目难度（1–5）——难题答对拉高、简单题答错拉低。
- 每个知识点的水平分：

  ```
  level = round0.5( 5 × Σ(w_i × s_i) / Σw_i )，再截断到 [1, 5]
  ```

  其中 `s_i` 为该知识点各题的得分（0–1），`w_i` 为对应难度；`round0.5` 为半向上舍入到 0.5 档（2.25 → 2.5，2.75 → 3.0）。知识点内无题 → 不写入矩阵（出题约束保证每知识点 ≥ 1 题，正常不会发生）。
- **语义**：全对 ≈ 5，全错/全跳过 ≈ 1（下限 1，与矩阵水平分区间一致）。

### 6.2 展示与确认

- 合成后展示能力矩阵（知识点 × 水平分）与判分摘要（每题得分），请学习者确认或质疑；确认后才写入。

### 6.3 写入 profile.md（op=placement）

调用 `scripts/profile.py`，`op=placement`，`results` 为合成后的知识点水平分数组：

```bash
python scripts/profile.py <input.json> <output.json>
```

```json
{
  "op": "placement",
  "date": "2026-08-20",
  "results": [
    { "topic": "pandas.Series", "score": 1.5 },
    { "topic": "pandas.DataFrame", "score": 1 }
  ]
}
```

- 输入输出格式见 `resources/profile-contract.md` §2–§3，用法与退出码见 §1；`date`/`profile_path` 缺省即可。
- **语义**：`results` 内知识点行整体按新值写入（来源「摸底测试」、日期 = date），不在 `results` 中的既有矩阵行保留；画像文件不存在时自动创建（与 onboarding 相同）；增量记录追加一条「摸底测试 → 初始矩阵」。**重走起步重新摸底时**：`results` 内知识点行会被**重置**为新摸底结果（覆盖该知识点此前的验收/复习增量；历史仍保留在增量记录中）——写前须明确告知学习者这一语义，经确认后才写（护栏 approval）。
- **approval 护栏**：`profile.py` 会**原地改写** `profile.md`，属持久层修改，执行前先经学习者确认（SKILL.md 护栏 approval）。
- **写入后**：简述矩阵已建立（可列出知识点数量），进入起步流程下一步（ticket 10 计划生成与三验证）。

## 7. 边界与护栏

- 不越过本流程：不生成每日计划（ticket 10）、不写 `progress.md`（ticket 12）、不更新复习调度表（ticket 03/13）、不新增或改写 `sources/` 资料。
- 范围驱动：题目只出自 `scope_covered`；`scope_excluded` 领域不考；判分不超出范围外知识。
- 不代答、不提示：作答阶段 agent 不给答案或提示；答不出按 0 分记，不引导猜答案。
- 判分透明：简答/实操逐条给要点得分；学习者质疑时复核，改分说明理由。
- 题量固定：15–20 题硬约束；不临时加题、不删题凑数。
- 中途退出：未完成判分/未确认合成结果**不写矩阵**（不写半成品）；下次可重新开始摸底。

## 8. 验证方式

- 本流程为对话式流程，按 spec「测试 seam」**不设自动化 seam**，构建后通过**实际演练验证**：模拟出题（范围驱动、难度梯度）→ 混合式作答（含一次"不会"跳过、一次简答、一次实操）→ 对照评分标准判分 → 难度加权合成 → `profile.py op=placement` 写矩阵 → 检查 `profile.md` 原文（初始矩阵行来源「摸底测试」+ 增量记录）。演练产物存于 `.scratch/python-coach/rehearsal-09/`。
- **演练记录（2026-08-20，ticket 09 构建时）**：范围 `scope_covered = [语法基础, 数据分析（pandas）, Excel 处理, 数据可视化]`（来自演练 plan.md 草案），出题 18 题（选择 10 + 简答 4 + 实操 4；难度 1–5 全覆盖、低档多于高档：d1×2、d2×8、d3×4、d4×3、d5×1；10 个知识点、每知识点 ≥ 1 题、每子领域 ≥ 2 题）——**转写摘录**：教练"题目都来自你确认的范围：语法基础、数据分析（pandas）、Excel 处理、数据可视化。答不出的说'不会'。" → 学习者逐题作答（Q4 实操函数答"不会"跳过、Q8 简答给部分代码、Q13 实操贴片段缺行数统计）→ 教练逐题判分（选择题 0/1；简答/实操按要点给 0.5）→ 合成：`变量与数据类型` = round0.5(5×1/3) = 1.5、`条件与循环` = 1、`函数` = 1（全跳过）、`pandas.Series` = round0.5(5×2/7) = 1.5、`pandas.DataFrame` = 1、`数据读取与筛选` = 2.5、`Excel 读写` = round0.5(5×2.5/4) = 3、`数据清洗` = round0.5(5×2/6) = 1.5、`matplotlib 基础绘图` = round0.5(5×3/4) = 4、`图表定制` = round0.5(5×2/6) = 1.5 → 学习者确认 → `profile.py op=placement` 写矩阵，退出码 0 → 检查 `profile.md` 原文：10 行初始矩阵（来源「摸底测试」）+ 增量记录「摸底测试 → 初始矩阵」一条，符合 §6 预期。
