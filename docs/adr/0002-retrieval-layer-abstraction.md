# 检索层抽象：数据格式先行，向量引擎后置

v0 阶段的资料检索使用「关键词检索 + 统一检索层接口」，不引入向量数据库。理由：当前资料量仅几十份文档，向量检索收益趋近于零；环境无嵌入 API key（云嵌入不可用），本地嵌入模型在 Python 3.14 上兼容性有风险。但为满足"升级后直接复用现有向量库"的诉求，将资料统一存储为带 frontmatter 元数据（标题/来源 URL/主题标签/日期/摘要）的 Markdown 于 `sources/`，并在技能内定义统一的检索层接口——输入查询、输出资料列表。升级到 plugin/应用时，同一份数据直接灌入向量库，仅替换检索层实现，数据零迁移。

**Status**: accepted

**Considered Options**: v0 直接上向量库（LanceDB/ChromaDB，需嵌入模型来源且承担 Python 3.14 兼容风险，弃）；v0 无检索层纯靠模型记忆（幻觉风险，弃）；文件库 + 检索抽象层（采纳）。

**Consequences**: 检索层接口的输入输出格式成为技能内契约；`sources/` 的 frontmatter 字段（标题/来源/主题/日期/摘要）即未来向量库的切块元数据，字段设计需保持稳定。
