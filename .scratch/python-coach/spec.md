# Spec: python-coach — AI-Native Python Learning Coach

**Status**: ready-for-agent

## Problem Statement

学习者使用通用对话式 AI（如 ChatGPT 网页版）学习 Python，存在四个痛点：

1. **计划难验证**：学习者对 Python 不熟悉，无法判断 AI 生成的学习计划是否合理、内容是否有可靠来源、是否符合自身水平；
2. **交互繁琐且无工具**：网页版无法调用系统工具（检索、文件操作），交互过程冗长；
3. **上下文过长**：学习进程推进导致对话上下文累积，造成设备负担并影响学习质量；
4. **缺乏适配性**：学习计划没有基于学习者的行为、性格、压力承受力等特征定制。

此外，学过的知识会遗忘，缺乏有效的复习机制。

## Solution

一个以 AI 为核心的个人学习教练 `python-coach`（v0 形态：DeepSeek Harness 技能集），围绕「计划 → 执行 → 反馈 → 验收 → 总结 → 复习」闭环运转：

- **目标驱动**：计划生成前先澄清"想用 Python 做什么"的具体目标，圈定所需子领域，并显式声明范围边界；
- **三验证**：计划落盘前经真实来源检索核查（真实性）、独立评审 agent 审视（合理性）、对照用户画像（适配性）；
- **摸底测试**：计划前做范围驱动的分知识点摸底测试（15–20 题），产出能力矩阵；
- **每日闭环**：每日任务在开始学习时生成单文件 HTML 执行视图（当日知识、链路、目标、来源），完成后经混合式验收（agent 评分 70% + 自评 30%），写当日总结入学习进度，确认后删除网页；
- **上下文管理**：每学习日新开一个会话，旧会话归档不延续（不物理删除）；
- **复习机制**：每节课输出复习快查文档（用户可读、按课程一份），间隔重复（艾宾浩斯：1→3→7→15→30 天）调度复习，掌握度与能力矩阵共用一套数据；
- **失控防护**：rules（护栏章节 + 范围声明）/ permission（文件沙箱）/ approval（破坏性操作确认）三层面。

**形态演进**：v0 技能集 → 包装为 plugin → 逐步升级为独立应用。闭环逻辑与载体解耦（scripts 纯逻辑跨形态复用，检索层为抽象接口）。

## User Stories

1. 作为学习者，我想在开始前用一句话说出学习目标，以便工具据此圈定我真正需要的 Python 子领域。
2. 作为学习者，我想看到学习计划显式声明的范围边界（覆盖什么、不涉及什么），以便我能验证它没有跑偏。
3. 作为学习者，我想在计划落盘前看到每条计划项的可靠来源引用，以便我相信计划内容不是编造的。
4. 作为学习者，我想让一个独立的评审 agent 审视计划的主题顺序、深度与每日份量，以便发现我察觉不到的教学问题。
5. 作为学习者，我想在生成计划前做一次摸底测试（15–20 题、覆盖范围声明内知识点、难度梯度 1–5），以便得到按知识点分维度的能力矩阵而不是一个总分。
6. 作为学习者，我想用一份 onboarding 问卷（8 题）建立初始画像（目标、水平自评、时间预算、风格偏好、压力自评、节奏、经历、复习意愿），以便后续计划适配我的特征。
7. 作为学习者，我想每天开始时看到当日任务的单文件 HTML 视图（知识内容、完整链路、目标清单、参考来源），以便我清楚地知道今天学什么、为什么学、从哪来。
8. 作为学习者，我想按计划完成当日任务并向教练反馈进展，以便教练能监督和辅助我的实操。
9. 作为学习者，我想在任务完成后提交当日证据（代码/运行结果/回答），以便教练对照当日目标核查我的完成情况。
10. 作为学习者，我想在教练给出完成度评估后确认或质疑，以便最终判定权在我手里。
11. 作为学习者，我想每天的验收按「agent 评分 70% + 自评 30%」合成完成度，以便评分既有证据基准又保留我的主观体验。
12. 作为学习者，我想在验收时反馈今日难度（太难/刚好/太简单），以便后续计划调整难度档位（该反馈独立记录，不混入完成度分）。
13. 作为学习者，我想在验收通过后看到当日总结写入学习进度，以便我的学习轨迹持久累积。
14. 作为学习者，我想在当日任务完成后由教练提出删除当日网页、经我确认后清除，以便网页不累积、不干扰后续学习。
15. 作为学习者，我想每个学习日从一个新会话开始、旧会话归档不延续，以便上下文保持精简、学习不受历史拖累。
16. 作为学习者，我想每节课结束后得到一份复习快查文档（按课程一份，知识点一行：概念+代码+坑+来源），以便我快速回忆历史知识。
17. 作为学习者，我想按知识点、按日期直接查阅复习快查文档，以便我能自主定位想复习的内容。
18. 作为学习者，我想每天会话开始时教练检查到期知识点并出题考察（间隔重复：1→3→7→15→30 天，未通过重置回 1 天），以便对抗遗忘曲线。
19. 作为学习者，我想复习考察的得分也写回掌握度，以便复习与学习共用同一套能力数据。
20. 作为学习者，我想在学新课时被随机抽查 2 个历史知识点热场，以便回顾热身。
21. 作为学习者，我想教练严格遵守范围声明、不偏离今日任务加戏，以便学习进程可控。
22. 作为学习者，我想教练给出的关键事实都带来源依据，以便内容可追溯、可信。
23. 作为学习者，我想持久层文件（计划/进度/画像/资料）的修改需确认、删除需显式批准，以便我的学习数据不被误操作。
24. 作为学习者，我想所有自动化流程有轮次/步骤上限，以便不出现空转死循环消耗资源。
25. 作为学习者，我想技能的所有纯逻辑（检索、调度、合成、画像更新、网页生成）有自动化测试，以便后续优化不破坏已有行为。

## Implementation Decisions

### 形态与载体

- v0 实现为 DeepSeek Harness 技能集，单入口技能 `python-coach`；后续包装为 plugin，再升级为独立应用。
- 技能（程序）与数据分离：技能存于用户技能根目录，数据文件存于项目工作目录。

### 数据文件（持久层）

- `plan.md`：当前学习计划——学习目标、范围声明、每日任务清单、计划项来源引用。
- `progress.md`：逐日学习进度，由每日总结追加。
- `profile.md`：用户画像——onboarding 问卷结果（8 题）、摸底能力矩阵、验收/复习增量。
- `sources/`：资料库——带 frontmatter 元数据（标题/来源 URL/主题标签/日期/摘要）的 Markdown，供检索层使用；格式即未来向量库切块数据（ADR-0002）。
- `review/`：复习快查文档（按课程一份，如 `01-pandas-groupby.md`）。
- `review/schedule.md`：复习调度表——知识点 → 掌握度 → 下次复习日。

### 检索层（唯一抽象接口，ADR-0002）

- 统一契约：输入查询 → 输出资料列表（标题/来源/摘要/链接）。
- v0 实现：关键词检索（glob/grep）+ web_search/web_fetch 补充。
- 升级时仅替换实现为向量检索，流程代码不变。

### 计划验证（落盘前，multi-agent）

- 计划草案生成后、落盘前，起独立评审 agent（子代理），输入学习目标 + 范围声明 + 计划草案，输出三份评审：真实性（逐项对照检索来源）、合理性（顺序/深度/份量）、适配性（对照画像）。
- 评审问题清单 → 主 agent 修订计划 → 评审通过才落盘。

### 摸底测试与能力矩阵

- 摸底测试：15–20 题，范围声明内各知识点覆盖，选择题约 10–12 题 + 简答/实操约 5–8 题，难度梯度 1–5。
- 作答方式：混合式——选择题对话内直接选，简答/实操贴文字或代码。
- 产出：能力矩阵（知识点 × 水平分 1–5），存 `profile.md`。

### 混合式验收与完成度

- 流程：学习者提交当日证据 → agent 对照当日目标核查给结论（完成/部分完成/未完成 + 理由）→ 学习者确认 → 写当日总结。
- 完成度评分：1–5 分制，合成规则 `0.7 × agent 评分 + 0.3 × 自评`；难度反馈独立记录，不影响完成度分，只影响后续计划难度档位。
- 验收结果写回能力矩阵（完成度高 → 该知识点水平 +0.5，上限 5）。

### 当日执行网页

- 每日任务开始时生成单文件静态 HTML（自包含、可离线打开），内容包括：当日知识内容（概念+示例）、完整链路（目标→今日位置）、今日目标清单（对照范围声明）、参考来源链接。
- 生成逻辑：输入 plan.md + 当日任务 → 输出 HTML。
- 清除：验收完成、当日总结写入后，agent 提出删除、学习者确认后删除（approval 护栏）；HTML 模板代码留在技能内可复用，仅删当日渲染实例。
- 与复习快查文档分工：网页 = 当日临时执行视图（用完即删），快查文档 = 持久知识沉淀。

### 上下文管理（ADR-0001）

- 每学习日新开会话，旧会话归档不延续；持久信息经每日总结入 `progress.md`。

### 复习与间隔重复

- 每节课输出复习快查文档一份，用户可读，支持按知识点/日期查阅。
- 调度：间隔重复，1 → 3 → 7 → 15 → 30 天；考察通过推迟下一轮，未通过重置回 1 天。
- 掌握度与能力矩阵共用同一数据结构（知识点 × 评分）；复习得分与验收得分都写回掌握度。
- 会话开头检查 `review/schedule.md` 到期知识点，先复习再学新课；新课开头随机抽查 2 个历史知识点热场。

### 失控防护（rules / permission / approval 三层面）

- **rules**：SKILL.md 固定「护栏」章节（每次加载必读）——今日任务 + 范围声明约束块、关键事实须引用来源、运行参数上限（子代理轮次上限、每日会话步骤上限）。
- **permission**：DSH 文件沙箱，持久层文件按需限制写权限。
- **approval**：持久层文件写操作需确认，删除操作显式批准；当日网页删除同样走确认。

### 测试 seam（单 seam）

- 唯一测试 seam：`scripts/` 下纯函数脚本，以「读输入文件 → 写输出文件」契约测试。
- 覆盖五块纯逻辑：检索层、间隔重复调度、完成度合成、画像更新、网页生成。
- 对话式流程（计划生成、验收对话）不设自动化 seam，构建后通过实际演练验证。

## Testing Decisions

- **好的测试标准**：只测外部行为（输入文件 → 输出文件的契约），不测实现细节。
- **被测模块**：`scripts/` 下五个纯函数模块——检索层、间隔重复调度、完成度合成、画像更新、网页生成。
- **测试形态**：以样例输入文件驱动脚本，断言输出文件内容（如：给定掌握度与考察结果，断言 `schedule.md` 的下次复习日；给定 agent 分与自评分，断言完成度；给定 plan.md 与当日任务，断言 HTML 含目标清单与来源）。
- **先例**：v0 无既有测试先例；测试框架采用脚本语言自带的断言方式（如 Python unittest 或轻量断言脚本），随技能集一并落地。

## Out of Scope

- 多用户/产品化：v0 为单用户个人工具，无鉴权、无部署、无服务端。
- 真向量库引擎：v0 不引入向量数据库（ADR-0002），仅建立数据格式与检索层抽象。
- 物理删除历史会话：采用归档而非删除（ADR-0001）。
- 复杂心理测评量表：画像采用 8 题问卷 + 增量观察，不做标准化心理量表。
- 网页动态交互/本地服务器：当日执行视图为静态单文件 HTML。
- 非 Python 学科：v0 锁定 Python（目标驱动圈定子领域）；引擎通用性留待后续抽象。
- 多项目共用画像：数据放项目工作目录，不抽用户级（后续如需再升级）。

## 决策记录（2026-08 修订评审：目录化与生命周期）

> 本 spec 为设计基线；评审后的修订方案（`docs/revision-plan.md`）按批次实施，实施的决策逐批回写此处保持同步。

- **工作区布局**：`python-coach/`（技能本体，只读）+ `.python-coach/{state,tmp}`（使用期数据目录，每工作区独立）+ `exercises/`（每日练习）+ `project/`（最终项目）。
- **正式状态目录**：六件套（plan / progress / profile / sources / review / review/schedule）一律在 `.python-coach/state/`。
- **过程文件目录**：初始化 JSON、计划草稿/修订记录、评审出入包、自检副本、脚本 in/out JSON 放 `.python-coach/tmp/`，**所属阶段完成即清**；会话结束 `.python-coach/tmp/` 全清、`state/` 只剩六件套。onboarding 输入 JSON 起步期间暂存 `state/`（可能跨会话），起步完成即清。原设计里的 `.python-coach/audit/` 取消。
- **路径约定**：脚本默认路径值**不变**；使用阶段一律**显式传** `.python-coach/state/…` 路径（相对当前工作区解析）。
- **项目边界**：当前项目 = 本工作区内的 `.python-coach/ + exercises/ + project/`，其余目录一律不读不写。
- **清理权限**：过程文件清理为 agent 内部动作，不需逐条向学习者确认；**当日执行网页删除除外**——须学习者显式批准（approval 护栏）。

## 决策记录（2026-08 修订评审：前置能力机制）

> 批次 2（分层矩阵+前置）实施，决策 2/3/13/14 落盘。

- **能力矩阵分层（决策 2）**：领域 → 子领域 → 知识点 + 独立「前置能力」层；`类型 = 知识点 | 能力`。一张扁平表加列（`| 领域 | 子领域 | 知识点 | 类型 | 水平分 | 前置状态 | 更新时间 | 来源 |`），不建分组子表；`profile.py` 按列解析，旧 4 列画像容错（视作知识点行，写回升级 8 列）。
- **前置声明（决策 3.2）**：plan.md 每个 Day 区块新增 `- 前置：<知识点/能力名，逗号分隔>`，名称与能力矩阵行对齐；无前置则省略。
- **前置评估（决策 13）**：摸底测试新增前置能力评估题组（对能力行 2–3 问快速评估），标记 `具备 | 未具备`，随 `op=placement` 以能力行写入矩阵。
- **判定规则（决策 13）**：知识点前置 → 矩阵水平分 ≥ 3 视为具备（< 3 为缺口）；能力前置 → `前置状态 = 未具备` 即为缺口（二值）。
- **两层校验（决策 3/14）**：计划生成阶段逐日核对前置、有缺口自动插入"补前置天"并入总天数 T；每日行前读当日 `- 前置：` 分级处置——严重缺口（能力未具备或前置 ≤ 1.5 分）暂停回计划补前置天、轻度缺口（1.5<分<3）当日补讲导入段并在总结注明。
- **能力行边界**：无水平分，不参与子领域均值、不进复习调度表、不接受验收/复习增量（只在摸底/计划修订时更新前置状态）。

## 决策记录（2026-08 修订评审：矩阵外新增通道）

> 批次 4（新增知识通道）实施，决策 5/15 落盘。

- **触发（决策 5）**：`op=acceptance` 或 `op=review` 的 `topic` 不在能力矩阵时，从「profile.py 报错退出」改为**暂停并进入显式通道**：向学习者说明"学习中出现了新知识点 X，将加入能力矩阵并纳入复习调度，是否确认？"；确认后写回，拒绝则跳过该 topic 并记录。
- **三同步**：`profile.py`（`add_new: true`）新建矩阵行——知识点行初值：验收 = 完成度、复习通过 2.0（与 schedule.py add 默认掌握度一致）/未通过 1.0；能力行（`type = 能力`）写前置状态二值；来源 `验收新增 Day N` / `复习新增`。配套 `schedule.py op=add` 纳入调度表 + `review.py op=append` 追加到当日课快查文档（新知识点无独立课程归属，挂当日课、topics 并入）。未带 `add_new` 仍报错（不静默放宽矩阵约束）。
- **防污染（决策 5/16）**：`source` 标记 + 学习者显式确认兜底；`scripts/check.py` 对「新增知识点/新增能力」日志行跳过验收口径核对（通道是确认过的例外）；输出带 `added: true` 供 agent 识别新增行。
- **运行期留痕（决策 15）**：矩阵新增（确认/被拒）记入 `.python-coach/state/decision-log.md` 单文件一行式（`YYYY-MM-DD | 矩阵新增知识点 | …`），`check.py` 校验其可读性与日期合法。
